# ADR-0002: Spring Boot 4.1 / Java 25 を採用する

- ステータス: Accepted
- 日付: 2026-09-19

## 背景

新規プロジェクトのフレームワークとランタイムのバージョンを決める必要がある。
ポートフォリオとしては「現在の実務で使われている構成」であることが重要で、
古い構成は技術キャッチアップができていない印象につながる。

## 検討した選択肢

### 案 A: Spring Boot 3.5 / Java 21

- 利点: 情報量が多く、トラブルシューティングが容易
- 欠点: 3.5 系は 2026 年 6 月 30 日に無償サポートが終了しており、
  以降に見つかった脆弱性の無償修正がない。新規採用する理由がない

### 案 B: Spring Boot 4.1 / Java 25

- 利点: 最新安定版（4.1.0 は 2026 年 6 月 10 日リリース）。
  Java 25 は 2025 年 9 月リリースの最新 LTS で、Spring Boot 4 が推奨するバージョン。
  Jakarta EE 11 / Hibernate ORM 7 / Jackson 3 という現行世代の構成になる
- 欠点: 日本語の情報が相対的に少ない。ライブラリの対応状況を個別に確認する必要がある

### 案 C: Quarkus / Micronaut

- 利点: 起動時間とメモリ消費で優れる
- 欠点: 国内のバックエンド求人は Spring Boot が圧倒的多数で、転職目的には合わない

## 決定

案 B（Spring Boot 4.1 / Java 25）を採用する。

欠点として挙げた「日本語情報の少なさ」は、むしろ調べて解決した過程を
作業メモとして残せるためポートフォリオ上はプラスに働くと判断した。

## 結果

- ビルドの Java toolchain、Docker のベースイメージ、CI の setup-java を
  すべて Java 25 に揃える
- Spring Boot 4 で追加された REST API バージョニングと仮想スレッドを積極的に使う
- Jackson 3 がデフォルトになっているため、Jackson 2 前提のライブラリを入れない
- 一部のサードパーティライブラリ（springdoc など）は Boot 4 対応版のバージョンを
  明示的に指定する必要がある
